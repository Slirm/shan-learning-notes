# 学习笔记模板与取舍标准

按材料类型选择模板。模板规定信息顺序，不要求机械保留所有标题。

所有笔记统一使用以下顶部属性：

```yaml
---
title: 笔记标题
date: YYYY-MM-DD
tags:
  - 可选标签
source: https://完整原始链接
---
```

`title`、`date`、`source` 必须保留；`tags` 整项可以省略，保留时最多两个。`source` 直接写完整 URL。正文中的仓库或原文地址使用 `[项目仓库](URL)` 或 `[阅读原文](URL)`，确保 Obsidian 可点击。

项目笔记底部“协议与商用”统一使用 Obsidian callout `> [!important] 协议与商用`；许可证链接使用 Markdown 格式。

## 1. 导航型项目

适用于资源目录、API 清单、工具导航。通常保持很短，不写目录结构、维护脚本、贡献流程或学习路径。

```markdown
---
title: 项目名称 项目学习笔记
date: YYYY-MM-DD
tags:
  - 开源项目
source: https://项目原始链接
---

# 项目名称 项目学习笔记

[项目仓库](https://项目原始链接)

一句话说明它是由谁维护、收录什么、主要用途是什么。

## 1. 怎么使用

用一个具体需求演示完整流程：
1. 找到相应分类；
2. 选择目标条目；
3. 查看必要字段；
4. 进入原始资源或官方文档；
5. 在自己的程序或工作中使用。

## 2. 怎样读懂表格

| 字段 | 含义 | 注意 |
|---|---|---|
| 字段名 | 简明解释 | 仅保留实际使用所需提示 |

列出最容易误解的两三个字段。若筛选条件有典型组合，用一行代码或短句说明。

> [!important] 协议与商用
> 项目采用 [许可证名称](许可证链接)。
> 说明商业使用条件，并明确提醒：仓库许可不等于所收录第三方资源的许可。
```

## 2. 工具、插件或整合包

适用于一键部署工具、桌面软件、插件、CLI 和封装项目。重点讲清它与上游项目的关系、安装入口和第一次成功使用。

```markdown
---
title: 项目名称 项目学习笔记
date: YYYY-MM-DD
tags:
  - 开源项目
  - 工具
source: https://项目原始链接
---

# 项目名称 项目学习笔记

[项目仓库](https://项目原始链接)

用一两句话说明项目是什么、解决什么问题。若它是另一项目的封装或插件，明确双方分工以及能否独立运行。

## 1. 怎么安装或怎么使用

1. 写清前置条件与下载或安装入口；
2. 给出启动步骤；
3. 说明首次运行需要选择的选项；
4. 给出最常用操作；
5. 说明结果保存在哪里或如何获得输出。

## 2. 关键选项或核心功能

只保留会影响首次选择或实际使用的项目，可用小表格说明。不要逐项搬运 README 功能清单。

## 3. 重要注意事项

列出会导致功能受限、运行失败、数据暴露或结果不可用的条件，例如系统、路径、联网、账号、浏览器、实验功能或素材限制。

> [!important] 协议与商用
> 项目采用 [许可证名称](许可证链接)。
> 说明商业使用条件、署名要求和相关第三方许可边界。
```

## 3. 库、框架或开发工具

只有在普通使用步骤不足以理解项目时，才加入核心概念和最小示例。

```markdown
---
title: 项目名称 项目学习笔记
date: YYYY-MM-DD
tags:
  - 开源项目
  - 开发工具

# 项目名称 项目学习笔记

[项目仓库](https://项目原始链接)

说明项目解决什么开发问题，以及主要使用场景。

## 1. 安装与最小使用

保留必要依赖、安装命令和最小可理解示例。示例用于解释核心概念，不追求覆盖全部 API。

## 2. 核心概念或工作流程

解释理解示例所必需的两到五个概念，以及它们如何协作。避免展开完整源码架构。

## 3. 注意事项

保留版本要求、常见限制和重要配置。

> [!important] 协议与商用
> 项目采用 [许可证名称](许可证链接)。
> 说明商业使用条件与相关第三方许可边界。
```

## 4. 文章或论文

文章不套项目的“安装、功能、许可”结构。围绕理解原意进行提炼，不随意添加项目式评价。

```markdown
---
title: 文章标题 学习笔记
date: YYYY-MM-DD
tags:
  - 可选主题标签
source: https://文章原始链接
---

# 文章标题 学习笔记

[阅读原文](https://文章原始链接)

用一两句话说明文章讨论的问题和核心结论。

## 1. 文章主线

按作者的论证顺序列出关键环节，而不是逐段复述。

## 2. 必须理解的概念

只解释会妨碍理解正文的术语或背景。

## 3. 关键论据与适用边界

区分事实、作者观点、假设与推论；保留重要证据、成立条件和明确局限。

## 4. 回顾要点

用少量条目记录日后容易忘记或误解的内容。避免重复全文。
```

## 内容取舍优先级

空间优先分配给：

1. 项目或文章的独特价值；
2. 第一次使用或理解所需的信息；
3. 容易导致失败或误判的限制；
4. 许可和商用边界；
5. 有助于回忆的具体例子。

优先删除：

- 对项目背景的空泛赞美；
- 与当前读者无关的目录和源码文件说明；
- 重复表达同一功能的句子；
- 完整功能清单和高级命令；
- 泛化的“建议进一步学习”；
- 没有原文依据的优缺点判断。
